## Proposed learner event contract (not implemented)

Keep the private content snapshot read-only and learner data in a separate local SQLite database. Do not commit learner data. Bind every completed self-assessment to an immutable content snapshot identity and exact (artifact SHA-256, unit ID), a pseudonymous local learner ID, attempt/event ID, UTC timestamp and rating. Record a cluster revision and ID only when supplied by a validated mapping; never use a bare mutable label as identity. Do not store free-text learner answers in the initial MVP. Exclude review-required units at presentation and persistence boundaries. Revalidate eligibility on selection and before recording; fail closed if content identity or revision cannot be resolved.

An accepted event follows the existing PracticeSession attempt -> reveal -> assess lifecycle. Enforce it in the application boundary; a rating alone is not proof of unaided recall. A stable unique event ID makes identical replay idempotent and conflicting replay an error. Serialize appends per learner, reject backdated events for the same unit in the pilot, and commit event plus derived state atomically. Keep append-only event history as authority; derived state must be replayable by scheduler version and event order. Store UTC times as integer epoch seconds and reject ambiguous naive timestamps. Do not silently migrate learning history between content revisions or merge mastery across clusters.

## Proposed deterministic pilot scheduler (not implemented)

Use per-unit due state first. Cluster membership can prioritize diversity, but cannot propagate mastery, reduce another unit's due burden or count identical prompts as independent evidence. Eligible units only; gated units never appear in the due/new queue. A versioned baseline, not a validated FSRS implementation, can use initial intervals again=10 minutes, hard=1 day, good=2 days, easy=4 days. Subsequent again resets to 10 minutes; hard multiplies the prior interval by 1.2 with a 1-day floor; good by 2 with a 2-day floor; easy by 3 with a 4-day floor. Use integer seconds with floor rounding and a 365-day cap. Compute due time from the actual event time, not the previous due date; overdue handling is deliberately simple. Select due units first, ordered by due time and stable revision/unit identity, followed by new eligible units within caller-supplied limits. Keep cluster-aware queue diversity and adaptive prioritization as later features, not mastery assertions.

Acceptance tests with synthetic fixtures: reject blocked/unknown revisions and invalid ratings; reject persistence before attempt/reveal/assessment; same-ID identical retry is a no-op, conflicting retry fails; no state change on transactional failure; independent learner and unit histories; due boundary and stable tie ordering; deterministic replay including restarts; interval bounds and again reset; same cluster or repeated prompt does not update another unit's state; content revision isolation and immutable content snapshot; no private data in Git. Evaluate learning outcomes before choosing or tuning a production scheduler.

The interval constants and local storage design are provisional engineering choices, not owner-approved efficacy settings. The current PR is documentation only; no runtime store, scheduler, synthetic test result or full CI result is asserted.
